# ROADMAP

> 目标不是「让机器人能回话」，而是「让她像一个住在群里的、有自己输入和想法的存在」。
> 每个阶段都能独立上线、独立回滚，验收不通过就不进下一阶段。

当前版本：**v1.0.0**（见根目录 `VERSION`）。下面的 S0–S5 是 v1.1.0 → v1.6.0 的候选内容。

## 设计约束（先定死，后面都按它来）

1. **接入层可替换**：大脑只对传输层暴露 `POST /turn`、`GET /proactive`，换框架不重写业务。
2. **人格不外包**：system prompt 的拼装权在我们手里，框架只负责搬运消息。
3. **红线**：不代发、不点赞、不评论任何平台内容；只读、只记。
4. **可观测**：每次「说 / 不说」都写 `logs/decisions.jsonl`，每次 LLM 调用都写 `usage.jsonl`。
5. **单实例**：同一 QQ 号同一时间只跑一套消费端（本机桌面端 / 云端二者取一）。

## S0 · 可观测与工具化骨架（v1.1.0，约 1 天）

- `cloud/lib/llm.mjs`：`chatCompletion()` 返回 `usage`（prompt/completion/cacheHit/cacheMiss），
  每次成功调用追加一行到 `data/usage.jsonl`（不记正文）。
- 新增 `data/decisions.jsonl`：主动说话的每个 gate / 每次工具调用都留痕（与 `trace.jsonl` 合并或并存）。
- 定义 `POST /turn` 契约：`{conv, kind:'private'|'group', text, images?, sender}` → `{segments:[{type:'text'|'image'|'at',...}], think?}`；
  桥（或未来的框架适配器）只做搬运。
- 指令 `/用量`（今日 / 区间 / 按场景）、`/余额`（DeepSeek `/user/balance`）。
- 顺手省一笔：`prompt.mjs` 的时间上下文从「精确到分钟」降到「时段 + 日期」，让前缀缓存命中。

**验收**：现有行为零回归；`usage.jsonl` 能对上官方账单；`/用量` 与 `/余额` 可用。

## S1 · agent loop（v1.2.0，约 2–3 天）

- 工具集 v1（最多 3 步，每步 20s 超时，超时即降级为纯聊天）：
  `web_search` / `read_url` / `send_meme` / `remember` / `recall`；**视觉工具预留接口，本版不启用**。
- 工具调用写 `decisions.jsonl`（工具名、参数摘要、耗时、是否采用结果）。
- 触发纪律：仅当用户明确提问「查一下 / 是什么 / 怎么回事」或需要事实核对时才调工具，闲聊绝不调。

**验收**：20 条真实提问 A/B（有无工具）人工盲评；平均延迟增加 < 3s；不出现「工具失败还硬编答案」。

## S2 · 群聊注意力（v1.2.0 已上线，约 2–3 天）

- 群旁听缓冲（最近 20 条、只保留文本与发言者昵称），三种触发：
  被点名（+20）、话题命中语义记忆（+15）、气氛正向（+5）；基础速率 +3/h。
- 发言前三次 LLM：**旁听评分**（0–10，<7 放弃且 `impulse -= 30`）→ 起草 → 自检。
- `annoyance` 反感度：显式制止 +40、说完 3 分钟无人接 +10、群友抱怨 +50、被踢/禁言/撤回 +80；
  ≥60 该群冲动归零 + 冷却 12h，≥100 冷却 7 天并写进自我模型。
- 硬上限：阈值 120、消耗 120、**每群每日 1 条**、同群最小间隔 6h；静默 23:30–07:30 共用。
- 指令 `/闭嘴`（该群永久静音，写 `rules[]`）。

**验收**：连续一周真实群跑，日均主动发言 ≤ 1/群，0 次被踢/被投诉，`trace.jsonl` 每条都有可解释理由。

## S3 · 自己有输入（v1.4.0，约 2 天）

> **2026-10-24 增补**：先做的是「QQ 空间」这一路（用户 #3 需求），已随 **v1.3.0** 上线——
> A 档每天 21 点读一次动态写语义记忆（`data/semantic.json`，私聊 prompt 带最近 5 条），
> B 档每天最多 1 条纯文字说说（默认 `dryRun: true` 只生成不发布，`/空间 发` 可手发）。
> B 站 / 抖音见下，留待下一轮。

- **B 站**：定时（2–3 次/天）拉「热门 + 关注的 UP 主更新 + 评论区高赞」，每条记成
  `{"kind":"seen","platform":"bilibili","title","up","url","summary","tags","at"}`
  写进语义记忆；之后聊天时能被 `recall` 取出来自然带一句，不主动报流水账。
- **抖音**：只做**热搜 / 聚合榜单**（第三方聚合接口或开放榜单页），不碰客户端、不做自动化登录。
- 消费纪律：每个平台每天最多 1 条"我今天看到的"，且必须与当前话题相关才提。

**验收**：隔天问「你昨天看什么了」能答上来；不相关的话不会硬塞。

## S4 · 接入层可替换（v1.5.0，约 1–2 天）

- 用 150–250 行适配器把 `POST /turn` 接到 LangBot 或 AstrBot（二选一，倾向 LangBot：
  多流水线 + MCP + 更 agent 化），**大脑与人格一行不改**。
- 关闭框架自带 LLM 自动回复（避免双回复），只保留它的适配器 / WebUI / 统计。
- 可选：用框架的 WebUI 当控制台，token 面板与我们的 `usage.jsonl` 对账。

**验收**：私聊 / 群聊行为与 v1.4.0 一致；切换窗口 < 10 分钟；可随时切回自研桥。

## S5 · 记忆管理（v1.6.0，约 2–3 天）

参考 AstrBot 的上下文压缩机制（`astrbot/core/agent/context/compressor.py`），但补上它没有的「长期记忆」。
AstrBot 的做法可以概括成三件事：

1. **触发**：按 token 用量比例判断，`current_tokens / max_tokens > 0.82` 才压缩（`compression_threshold=0.82`）；
2. **切分**：按「轮」切，保留最近的约 **15%** token（`keep_recent_ratio=0.15`，上限 0.3），
   最新一轮永远原样保留；
3. **压缩**：把更早的轮次喂给 LLM 生成摘要（提示词要求「可无缝接着干活」，并明确「若任务进行中，
   结尾写上最新状态」），然后把结果拼成一对消息注入：
   `user: "Our previous history conversation summary: …"` + `assistant: "Acknowledged the summary…"`，
   最后接上保留的最近轮次。
   另有兜底实现 `TruncateByTurnsCompressor`（直接丢最早若干轮），以及基于估算的 `TokenCounter`。

我们要做的（三层 + 遗忘）：

- **L1 情节记忆**：近 N 轮原样（保持现在行为）；
- **L2 压缩摘要**：超过阈值时把更早的轮次压成「记忆摘要」，**落盘持久化**并按会话分桶
  （`data/summaries/<conv>.json`：`{summary, coveredUntil, updatedAt, tokens}`），每轮注入；
  摘要本身再超长时做「摘要的摘要」（AstrBot 没有这一层）；
- **L3 语义记忆**：事实/偏好/事件（人、喜好、约定、看过的内容），带 `importance` 与 `lastUsedAt`，
  检索用关键词 + 向量混合（先关键词，量大了再上 embedding）；
- **自我模型**：≤200 字的「我是谁 / 我和主人到哪一步了」，每次对话注入，只允许缓慢变化（防人格漂移）；
- **遗忘曲线**：`importance` 随使用衰减，30 天未命中的低分记忆降级归档（不删除，落 `archive/`）；
- **可解释**：`/记忆` 显示摘要与命中条目，`/忘记 <关键词>` 定点删除，`/记忆导出` 走备份服务。

**验收**：连续 300 轮对话后，机器仍记得早期关键事实（人名、约定、偏好）；
压缩后 system+摘要+最近的总 token 稳定在上限 70% 以内；人格与口癖无明显漂移（A/B 盲评）。

## 排期顺序

```
S0 ──► S1 ──► S2 ──► S3 ──► S4 ──► S5
 │      │      │      │      │      │
 账本   能力   群聊    输入   多平台  记忆
```

- S0/S1 是「能不能帮忙」的地基，先做；
- S2 是「像不像群友」的关键，做完就该在真实群里试一周；
- S3/S5 决定「她有没有自己的生活」；
- S4 只在需要多平台或想要控制台时才做，属于可选项。

## 明确不做

- 抖音客户端自动化、任何平台代发 / 点赞 / 评论；
- 2C2G 机器上跑无头浏览器（内存不够，真浏览需先升 4G）；
- 把人格 / 主动性外包给框架的默认 agent。
